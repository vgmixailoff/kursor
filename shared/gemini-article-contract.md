# Gemini article contract (evening canon, 31.08.2026)

**Модель:** `gemini-3.8-flash` (Cursor Cloud Agents).  
**Роль в пайплайне:** единственный автор всего русского текста, который
читают люди. Research — склад фактов (англ. ок). Sol/Тележенька/Лебедев
**не** переписывают финал.

## Выход: один JSON

Файл: `gemini-article.json` в article_dir.

Обязательные ключи:

| Ключ | Назначение |
|------|------------|
| `TITLE` | H1; искомое имя продукта в первой строке |
| `DESCRIPTION` | Тизер карточки Дзена / RSS, 80–180 знаков; ≠ TITLE ≠ opening |
| `COVER_LINE1` | Имя на обложке (крупнее) |
| `COVER_LINE2` | Вторая строка обложки (тоньше) |
| `COVER_PROMPT` | Legacy-сцена; **не** уходит в Kie (комикс берёт TITLE) |
| `COVER_ALT` | alt обложки |
| `BODY` | HTML статьи (без h1), ориентир 3000–6000, допустимо 2500–6500 знаков видимого текста |
| `INLINE1_ONIMAGE` … `INLINE4_ONIMAGE` | Подписи **на схему** (заголовок + 2–5 коротких проверенных подписей, каждая ≤70 знаков). Рендер — полезная диаграмма, не текстовый слайд. |
| `INLINE1_ALT` … `INLINE4_ALT` | alt инлайнов |
| `SCREENSHOT1_ALT/CAPTION` … `SCREENSHOT4_ALT/CAPTION` | Необязательные русские alt и видимая подпись для официальных скринов из Research, по порядку кандидатов |

`INLINE*_ONIMAGE/ALT` добавляй только при наличии фактуры для полезной схемы;
не придумывай карточки ради числа. Подписи должны быть понятны человеку,
который ещё не знает, что такое агентские системы и токены.
Если схема нужна, поставь в `BODY` пустой `<figure data-slot="inline_1"></figure>`
(соответствующий номер) сразу после абзаца, который она проясняет.
Inline Visuals заменит слот готовой схемой на этом месте. Cover делает
только отдельную обложку. Без схемы слот не ставь.
Для официального скрина Writer заранее даёт `SCREENSHOTn_ALT/CAPTION` по
кандидатам Research. Inline Visuals проверяет настоящий кадр; если подпись
не соответствует видимому, кадр не вставляется.

## Правила BODY (живой русский для читателя Дзена)

1. Видимый текст: ориентир **3000–6000** знаков с пробелами. Диапазон **2500–6500** допустим без подгонки; FAIL только за его пределами. Не раздувай бедную фактуру.
   Попадание в диапазон проверяет `scripts/excalibur_blog_body_len.py`.
   Не вставляй статью в Python и не пиши calibrate / test_precise / test_target:
   мимо диапазона правь один-два абзаца в `gemini-article.json`, не больше 3 раз.
   Одно точное число внутри диапазона не нужно.
2. Живой письменный русский для взрослого новичка, обращение на «вы». Меняй ритм предложений по смыслу. Структуру выбирай по фактам и типу материала, без единого шаблона на все выпуски.
3. Полный запрет канцелярита: «Важно отметить», «Следует подчеркнуть», «В современном мире», «данный», «осуществлять», «в рамках».
4. Без калек «ходит сам / кликает». Без голого слова «чат» в роли продукта.
5. Без стопки английских имён в тексте и заголовке.
6. `<blockquote>` — только настоящая цитата из исходных материалов с указанием автора, на естественном русском. Без источника не ставь цитату; статья может обойтись без `<blockquote>`.
7. Оформление: `h2`, списки и выделение — когда помогают чтению. Голых URL нет. Не добавляй FAQ, списки и цитаты ради шаблона.
8. Подзаголовки `h2` — живая мысль из текста (Что / Как / Зачем / Где или конкретный образ), а не штампованная инструкция.
   - НЕ заставлять каждый H2 начинаться с глагола «Создайте / Настройте».
   - H2 «Чем это не является» / «Что сделать сегодня» — **строго запрещены**.
9. Первый абзац статьи сразу живым языком отвечает на поисковый запрос из H1 (легкий SEO/GEO слой без бюрократии).
10. CTA ровно **один раз в середине**, одной живой фразой и с **одной** уместной ссылкой (не список, не в конце статьи).
   Выбери одну из трёх разрешённых ссылок:
   - Ковчег → `https://t.me/maya_pro`
   - Ковчег в MAX → `https://max.ru/maya_pro`
   - обучение Cursor+Make+AI → `https://kv-ai.ru/obuchenie-po-make`
11. `t.me/kovcheg_ai` **не существует**. Не писать «Ковчег AI». Один Telegram.
12. Имени Лебедева в тексте нет. Артур — тема/канал, не «слог Сола».

## TITLE (громкий и честный заголовок с искомым именем)

Единый заголовок для H1, RSS и карточки Дзена. Автор TITLE — тот же Writer/Gemini; применяй `skills/dzen-loud-headlines/SKILL.md` к фактам текущего выпуска:
1. Искомое имя продукта (поисковый запрос) — **ПЕРВЫМ**: «Cursor MCP: …», «Claude Code: …».
2. После двоеточия — **личная ставка и резкий поворот**: что читатель рискует потерять, ошибочно принять за правду или упустить. Ставка следует из фактов, не из фантазии.
3. Без стопки английских имён (например «Claude Code and Cowork» — FAIL).
4. Без эмодзи (никаких 💻, 🚀, 🔥).
5. Без шаблонов «пошаговая инструкция / чек-лист 2026» в роли заголовка.
6. Понятный глагол без дыр («сотрудники работают», а не «компания сидит»).
7. Разрешён смысловой КАПС для сильных слов. Запрещены выдуманные последствия, кликбейтные пустышки и SEO-хвосты («без копипаста», «за вечер»).

| Статус | Пример | Почему |
|--------|--------|--------|
| **GOOD** | Cursor MCP: сервер подключился — а команды НЕ РАБОТАЮТ | Имя первое, есть действие и ставка; подходит, только если статья разбирает именно эту ошибку |
| **GOOD** | Claude Code: агенты писали «сдал», а в трекере пусто | Имя первое, живая история, глаголы на месте |
| **FAIL** | Как подключить MCP-серверы в Cursor: пошаговая инструкция для автоматизации | Имя задвинуто в середину, штамп «пошаговая инструкция» |
| **FAIL** | 💻 Cursor MCP за 20 минут: подключите серверы! | Эмодзи, тайм-кликбейт, неестественный возглас |
| **FAIL** | Cursor and Make and n8n: автоматизация процессов | Стопка английских названий, нет живого глагола |

### Лёгкий SEO/GEO слой (не ломает живой слог)
- Имя продукта первым в H1 = первичный запрос в поиске Яндекса/Google.
- Первый абзац статьи сразу даёт ответ на этот запрос живой речью (без канцелярских определений).
- `title_seo`: тот же TITLE, без отдельного спокойного SEO-варианта и без обрезки до произвольной длины.
- `title_ctr`: тот же живой хук, строго без эмодзи.
- `title_aeo`: вопросительная форма исключительно для метаданных GEO/AEO (Яндекс Нейро / Perplexity / Google AI Overviews) — никогда не H1 и не RSS.
- Schema headline: тот же разговорный H1.
- FAQ и `<blockquote>` допустимы только при содержательной необходимости; не добавляй их ради AEO.
- Проверенные факты и ссылки на первоисточники сохраняются.

## Materialize

```bash
python3 scripts/excalibur_blog_gemini_materialize.py --article-dir <dir>
python3 scripts/excalibur_blog_gemini_article_gate.py --article-dir <dir>
```

Materialize пишет: `article.html`, `title-brief.json`, `description-brief.json`,
`cover/cover-text.json`, `drafts/writer.html`.

Отдельных агентов Title / Description / Cover-text **нет**. Другой агент
**не правит** строки Gemini, кроме CTA `href` при починке битой ссылки.
FAIL гейта → точечная правка исходного JSON в том же Writer Task и повторная проверка. Директор не переписывает текст и не запускает нового автора.
