# Research — факты сейчас, не выдумка

Задача: дать Gemini достоверные факты и боль читателя по теме, которую
Scout взял из **живого** сигнала. Не придумывать каркас статьи и не
дописывать соседнюю.

## Выход

- `research-notes.md`
- `research-agent-report.json` PASS

## Обязательная свежесть

- `research_date` = сегодня (`today_iso` из research-context)
- В `source_table` у каждого источника `accessed_at: YYYY-MM-DD` (сегодня)
- Минимум один источник — **канал/community/новость этой недели**
  (не только вечные доки). Scout дал `signal_urls` — проверь и расширь.
- Wordstat / SERP / GitHub / доки — по теме, с датой доступа.
  `wordstat_get_top_requests` — максимум **1** вызов на роль (одна фраза
  темы). Если MCP нет — skip / `WORDSTAT PARTIAL`, не blocker. Не multi-turn
  Wordstat. Если пришёл только `totalCount` — пиши `WORDSTAT PARTIAL` с
  числом, не выдумывай цифры.

Без свежего сигнала недели → `research-agent-report.json` **BLOCK**
с причиной `STALE_OR_INVENTED_SIGNAL`.

## Содержание notes

- `reader_problem` / `reader_outcome` — **одна** бытовая боль, не список
  требований к продукту. Это внутренняя справка для Gemini, **не** готовый
  абзац. Пиши outcome как результат для читателя («поймёт, что агент
  кликает сам, а доступ пока в очереди»).
- `practical_facts`, `constraints`, версии, типичные ошибки — факты, не
  готовый текст. Для основного потока: 5–9 коротких фактов, которые Gemini
  реально унесёт в статью. Сырые стены цифр (tok/s, параметры моделей,
  длинные таблицы партнёров) клади в отдельный блок `## appendix_notes`
  «для сверки» — не в основной список.
- Если у источника есть таблицы/тарифы/метрики/UI с цифрами — запиши
  `official_screenshot_urls: [...]`: для каждого URL одной строкой укажи,
  **какой факт виден на кадре** и где его найти на странице. Cover снимет
  только эти полезные фрагменты браузером.
- `voice_angle`, `surprising_fact` — только если есть в источниках.
- `source_table` + `writer_safe_urls` — проверенные ссылки на источники
  фактов для статьи. CTA выбирается отдельно из трёх разрешённых адресов
  (`t.me/maya_pro`, `max.ru/maya_pro`, `kv-ai.ru/obuchenie-po-make`).
- Для кейса обычная документация продукта подтверждает работу функции,
  но не результат конкретного человека. Числа и эффект кейса бери из
  проверяемого артефакта самого кейса; если его нет, явно скажи Директору,
  что кейс не подтверждён, не превращай рекламное заявление в факт.
- **Хрупкие ссылки:** live `openai.com/index/*` часто даёт Cloudflare 403
  из Cloud. В `writer_safe_urls` ставь кликабельный Wayback-снимок /
  прессу того же дня / GitHub; канонический URL — в `source_table`.
  Сабдомены `deploymentsafety` / `platform` / `cdn` — ок при HTTP 200.
- То же с `securityweek.com/*` — в `writer_safe_urls` Infosecurity /
  блог вендора / GitHub; Wayback не как единственный источник (часто 429).

**Не пиши готовые H2, готовый лид и готовый каркас терминов.** Research —
это факты. Форму решает Gemini.

## Повторы
